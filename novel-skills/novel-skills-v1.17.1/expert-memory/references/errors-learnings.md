### 1. 创作管理工具全景图
文档管理工具：
→ Obsidian/Notion：设定总表、角色档案（双向链接，关系可视化）

→ Word大纲：每章核心事件列表
AI辅助工具（2025年主流）：
→ 笔灵AI小说：专注网文风格，适合起稿/润色
→ DeepSeek：逻辑推理强，适合检查战力体系
→ Kimi：长文本分析，适合拆解爆款
→ 豆包：细节润色，适合对话优化
→ 文心一言：综合能力，兼顾各环节
### 2. 分阶段工具使用策略
起稿阶段：
→ 用大纲工具建立骨架（Obsidian/飞书）
→ 用AI分析同类爆款的结构（Kimi）
→ 用大纲确定战力体系（金字塔）
写作阶段：
→ 自己写核心情节和对话
→ AI辅助写过渡段落和环境描写
→ 人工审核AI生成内容（防OOC/防战力崩坏）
审核阶段：
→ AI做逻辑检查（DeepSeek）
→ 人工做情感检查（读出声）
→ 对照伏笔追踪表检查伏笔回收
### 3. AI协同写作的防崩指南
AI写作最大的问题是"遗忘"：
→ AI不记得前面写了什么
→ 需要人工做"上下文桥接"
解决方案：
→ 每章写完后，生成"本章摘要"（50字以内）
→ 把摘要喂给下一个AI写作环节
→ AI生成内容后，人工对照检查
防战力崩坏的AI检查清单：
① 检查本章中主角的能力描述是否与档案一致
② 检查本章出现的NPC实力是否在战力体系内
③ 检查本章的战斗结果是否有合理的原因
④ 检查本章的伏笔是否被正确埋下
### 4. 长篇创作的版本管理
每5万字建立一版备份：
→ 版本1.0（0~5万字）
→ 版本2.0（5~10万字）
→ 版本3.0（10~15万字）
→ 以此类推
命名规范：
→ 最终版：正文+时间戳
→ 中间版：正文+章节范围
→ 备份存储在云端（防本地丢失）

### 10.1 伏笔埋设三步法

伏笔是长篇连载的灵魂——让读者在回收时产生"原来如此！"的智力愉悦。但伏笔不是随便埋的，需要系统化的方法确保"埋得稳、记得住、收得响"。

三步法模板：

```
第一步：埋设（植入读者潜意识）
  核心：让伏笔"自然地"出现在非重点位置，不引起特别注意
  方法：
  - 嵌入场景描写中（作为环境细节的一部分）
  - 嵌入对话中（作为某句随口说的话）
  - 嵌入角色行为中（作为某个不起眼的动作）
  规则：伏笔出现时不能有"特写镜头"——一旦特写，读者就会记住，失去"原来如此"的效果

  模板："在描写[日常场景]时，顺便提了一句[伏笔元素]，像背景一样不起眼。"
  例：主角路过一个废弃的祭坛，作者只用了"杂草丛生的石台"一笔带过（→ 50章后这里是关键决战之地）

第二步：维护（定期刷新记忆）
  核心：让伏笔不被读者遗忘，但也不过早暴露
  方法：
  - 每20-30章让伏笔元素"轻微出现"一次（角色路过/提及/联想）
  - 出现时仍然不做特写（保持"不起眼"的状态）
  - 可以用不同的角色/视角提及同一个元素
  规则：维护的目的是"别让读者完全忘了"，不是"让读者意识到这是伏笔"

第三步：回收（产生顿悟快感）
  核心：在读者完全没想到的时机，用震撼的方式回收伏笔
  方法：
  - 回收时要"重新展示"伏笔的完整画面（闪回/回忆）
  - 回收时要展示伏笔的"新含义"（当时不起眼，现在意义重大）
  - 回收场景本身要有戏剧冲突（不是平淡地"想起来"，而是"在关键时刻恍然大悟"）
  规则：回收速度要快——从"意识到"到"恍然大悟"不超过3段话
```

### 10.2 线索密度公式

线索太稀疏，读者感受不到伏笔的存在；线索太密集，读者会觉得"这本书在刻意引导我"。线索密度公式帮助作者控制信息投放的频率。

```
密度公式：
  伏笔密度 = 伏笔元素出现次数 ÷ 总章节数

  稀疏密度（1:30~1:50）：用于"大伏笔"
    → 涉及核心世界观/最终Boss/主线真相
    → 全书可能只出现3-5次
    → 回收时需要"闪回"帮助读者回忆

  中等密度（1:10~1:20）：用于"中伏笔"
    → 涉及角色身世/势力关系/中期反转
    → 全书出现10-20次
    → 回收时读者应该有模糊印象

  密集密度（1:3~1:5）：用于"小伏笔"
    → 涉及单章内的悬念/小反转/幽默包袱
    → 回收时读者应该清晰记得

投放节奏：
  大伏笔：第N章埋设 → 第N+50~80章回收
  中伏笔：第N章埋设 → 第N+15~30章回收
  小伏笔：第N章埋设 → 第N+3~8章回收

禁忌：
  ❌ 伏笔密度全书一致（应该有疏有密）
  ❌ 大伏笔没有维护就直接回收（读者忘了）
  ❌ 小伏笔拖到30章以后才回收（读者已经不记得了）
```

### 10.3 回收验证清单

伏笔回收后，作者需要自我验证回收是否成功。一个成功的回收应该让读者产生"恍然大悟+情感冲击"的双重效果。

```
回收验证六问：

① 读者是否能回忆起伏笔？
  → 回收时是否提供了足够的"回忆触发器"？
  → 如果伏笔埋在50章以前，是否在回收前3章做了"二次暗示"？

② 回收是否产生了"新含义"？
  → 伏笔的含义是否在回收时发生了质变？
  → 例：之前只是"一块普通的石头"，回收时变成"封印万年的神器碎片"

③ 回收时机是否在情绪高点？
  → 是否在紧张/震撼/感动的场景中回收？
  → 平淡回收 = 浪费伏笔

④ 回收是否影响了剧情走向？
  → 伏笔回收后是否改变了角色的选择/局势的发展？
  → 没有剧情影响的回收 = 纯炫技

⑤ 是否有"回头看"的冲动？
  → 回收后读者是否想去翻看伏笔原始出现的章节？
  → 这是衡量伏笔质量的最高标准

⑥ 是否避免了"解说式回收"？
  → 回收是否通过行动/画面/冲突自然展现？
  → 不要让角色说出"原来如此！因为[伏笔解释]……"——太假
```

### 10.4 自检清单

- [ ] 每个伏笔是否完成了三步（埋设→维护→回收）？
- [ ] 大伏笔是否在20-30章维护刷新了一次？
- [ ] 伏笔密度是否符合公式（大伏笔稀疏、小伏笔密集）？
- [ ] 回收是否通过了"回收验证六问"？
- [ ] 是否避免了解说式回收（用行动/画面展示而非角色解释）？
- [ ] 回收后读者是否会产生"回头看"的冲动？
- [ ] 全书伏笔是否有"疏密交替"的节奏？

### 12.1 经验持久化铁律

> 来源：气功砍穿神魔/美食末世/鬼灭之刃项目实战，2026-04-08确立

```
铁律1：单章生成 >> 批量生成
  → batch模式产生230处不可逆场景双版本
  → 单章模式几乎无机械错误，效率10倍优势
  → 所有新项目强制采用单章模式

铁律2：Skills 升级闭环
  → 发现即汇报 → 执行升级 → 封装打包 → 版本号自增 → 记录在案 → 同步IMA
  → 不要等到session结束才汇报

铁律3：IMA按项目分文件夹
  → 知识库笔记必须按项目归类，不可全部混在同一目录
  → 结构：项目A/ 项目B/ 系统文档/

铁律4：项目压缩包每次变动后重新输出
  → 确保下一session能拿到完整项目快照

铁律5：写作批次不可贪多
  → 2-3章小批量尚可接受
  → 5章以上批量 = 引入不可逆质量问题
```
