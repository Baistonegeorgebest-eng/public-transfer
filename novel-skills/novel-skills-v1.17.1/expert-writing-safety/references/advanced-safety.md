## 经典技法补全

> 本章节补充可直接套用的经典技法模板，供创作者在实际写作中参考。

### 10.1 和谐词替换速查表

网络文学平台对敏感词的审查日趋严格，但创作者不需要牺牲表达力来换取合规。核心原则：用更精准、更有画面感的表达替代直白的敏感词，不仅规避风险，还提升文字质量。

替换策略模板：

```
暴力场景替换：
  ❌ "他一刀砍下了对方的头" → ✅ "刀光闪过，那人闷哼一声，身形轰然倒地"
  ❌ "鲜血喷涌而出" → ✅ "衣襟上绽开一朵暗色的花"
  ❌ "肠子流了一地" → ✅ "伤势极重，已无再战之力"
  原则：用结果暗示代替过程描写，用意象替代直白描述

情感/亲密场景替换：
  ❌ 直白的生理描写 → ✅ 用氛围、暗示、留白替代
  例：用"他俯身靠近，呼吸近在咫尺"代替直白描写
  例：用"帐幔落下，遮住了里面的光景"做留白
  原则：写"之前的氛围"和"之后的反应"，中间留白

政治/敏感话题替换：
  ❌ 直接引用现实政治事件 → ✅ 用架空设定映射
  ❌ 使用现实国名/地名涉及敏感 → ✅ 使用虚构名称
  ❌ 宗教/民族相关内容 → ✅ 完全架空信仰体系
  原则：任何可能引发争议的元素，都用"架空化"处理
```

### 10.2 安全描写模板：三段式安全框架

当剧情需要涉及暴力、黑暗、敏感内容时，使用三段式框架确保安全合规：**前置铺垫 → 安全描写 → 后置转向**。前置铺垫建立情绪氛围，安全描写用隐晦手法呈现内容，后置转向将读者情绪引导到积极方向。

```
框架模板：

① 前置铺垫（让读者心理准备）
  - 提前暗示"接下来会发生不好的事"
  - 用环境描写营造压抑氛围
  - 例："天色暗沉，山雨欲来。他推开那扇门，看到了不该看到的一切。"

② 安全描写（用隐晦手法呈现）
  - 用角色反应代替事件本身
  - 用旁观者视角保持距离
  - 用比喻和意象替代直白描述
  - 例：不写"杀人的过程"，写"门外的人听到了一声闷响，然后是死一般的寂静"

③ 后置转向（引导情绪走向积极）
  - 描写正义得到伸张
  - 描写受害者的恢复/希望
  - 描写主角对此事的态度和行动
  - 例："他合上了那扇门。这一笔账，他会连本带利地讨回来。"
```

### 10.3 敏感话题处理四步框架

当剧情需要触碰现实敏感话题（如校园暴力、家庭问题、心理健康等）时，使用四步框架确保既有深度又安全合规：

```
① 架空化处理
  将现实敏感话题嵌入架空世界观
  例：不写"校园霸凌"，写"宗门内门弟子欺压外门弟子"
  例：不写"家庭暴力"，写"修仙家族中的权力压迫"
  → 保留问题的内核，替换问题的外壳

② 视角聚焦于"修复"而非"展示"
  不要详细展示伤害过程
  将笔墨集中在：受害者如何走出来 + 旁人如何帮助
  → 读者获取的是"希望"而非"绝望"

③ 安排明确的正义结果
  作恶者必须受到惩罚（可以延迟但不能缺席）
  惩罚方式要符合世界观内的正义标准
  → 给读者一个情绪上的交代

④ 控制篇幅和频率
  敏感话题涉及篇幅 ≤ 该卷总篇幅的20%
  不要连续多章沉浸在负面情绪中
  → 保持阅读体验的整体积极
```

### 10.4 自检清单

- [ ] 所有暴力场景是否使用了"结果暗示"而非"过程直白"？
- [ ] 亲密场景是否采用了"氛围+留白"而非直白描写？
- [ ] 涉及现实敏感话题时是否做了"架空化处理"？
- [ ] 每个黑暗场景是否有对应的"后置转向"？
- [ ] 敏感话题涉及篇幅是否≤该卷的20%？
- [ ] 是否避免连续3章以上沉浸在负面/黑暗情绪中？
- [ ] 作恶者是否在合理篇幅内得到了明确的惩罚？

## 十、写作模式安全规范（v1.1新增）

### 10.1 铁律：单章生成 >> 批量生成

**来源**：气功砍穿神魔（batch模式）vs 美食末世（单章模式）对比实验（2026-04-08）

| 维度 | batch（批量）模式 | 单章模式 |
|------|-----------------|---------|
| 机械重复 | 230处残留（54完全重复+72双重分隔符+104场景双版本） | 几乎为零 |
| 跨章连贯性 | 差（各批次独立生成，缺乏上下文衔接） | 好（每章有完整前后文） |
| 质检效率 | 6轮20小时仍未根除 | 1轮2小时即达标 |
| 效率比 | 基准 | **10倍优势** |

**执行规则**：
```
✅ 必须：单章生成 — 每章独立生成，携带前一章结尾上下文
⚠️ 警告：2-3章小批量 — 仅在单章字数不足时使用，需附带衔接检查
❌ 禁止：5章以上批量生成 — 产生不可逆的场景双版本问题
❌ 禁止：批量生成后不做语义级质检就发布
```

### 10.2 场景双版本预防规则

**场景双版本**：batch模式下，模型在不同批次中生成**语义相同但措辞不同**的同一场景段落。这是batch固有缺陷，无法通过字符串去重检测。

**预防措施**：
```
① 新项目：直接采用单章模式，从根本上避免
② 旧项目（有batch历史）：
   → Post-Write验证时加入语义相似度检测（expert-quality-gate F类）
   → 全量审计时用段落级语义对比扫描
③ 发现场景双版本后：
   → 对比两版，保留质量更高的版本
   → 删除或重写较弱版本
   → 重新质检确认0残留
```

### 10.3 AI生成内容的指纹规避（2026平台适配）

平台AI检测核心逻辑：人类写作有随机性，AI没有。

**强制规避措施**：
```
① 每章开头人工写2-3句话（句式变化+长短交替）
② 加入角色口头禅（AI不会学口头禅）
③ 不连续3章用相同开头句式
④ 适当加入口语化表达（非严重typo）
⑤ AI辅助内容必须经过人工润色（修改量 > 50%）
```

## 十一、机械错误铁律速查（v1.1新增）

> 从气功砍穿神魔实战中提炼的不可违反规则

```
铁律1：单章生成 >> 批量生成（质量差异显著，不可妥协）
铁律2：每章开头必须人工写（防AI指纹检测）
铁律3：场景双版本是batch固有缺陷，无法事后根除
铁律4：Expert-writing-safety检查必须在Post-Write验证之前执行
铁律5：发现新的机械错误类型，立即更新本skill的分类体系
```
