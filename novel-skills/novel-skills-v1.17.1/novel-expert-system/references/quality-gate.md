## 第三层：质量门禁体系（扩充新增）

### 3.1 质量门禁的定义与意义

```
质量门禁 = 每个创作环节必须通过的最低质量标准
→ 没有通过门禁 = 不能进入下一环节
→ 从源头杜绝"带着问题写下去"的灾难

三层质量门禁：
├─ 门禁一【构思门禁】：世界观和角色设计是否通过？
├─ 门禁二【大纲门禁】：双轨大纲是否满足平台算法要求？
└─ 门禁三【成稿门禁】：章节是否通过 expert-quality-gate 的Post-Write验证？（模板检测+字数+连续性+节奏空洞）
│  └─ 未通过 → expert-revise-loop 修正 → 重验 → 仍不通过 → 记录 ERRORS.md（失败案例入档）← v1.46新增
```

### 3.2 构思门禁检查项

```
□ 世界核心冲突一句话能说清楚
□ 力量上限已明确（不是"最强"这种模糊词）
□ 差异化记忆点已确定
□ 主角身份标签一句话能说清楚
□ 主角核心动机明确且不可动摇
□ 主角至少有1个显著缺点
□ 主要反派有合理动机
□ 主要配角不超过5个，每个有独特作用
□ 势力不少于3个，势力之间有冲突逻辑
□ 合规检查通过（无敏感内容）
```

### 3.3 大纲门禁检查项

```
□ 核心主线一句话已确定
□ 3个核心转折点已规划
□ 爽点密度：每3章一个小爽点
□ 伏笔已标注回收节点
□ 开篇300字内出现核心冲突
□ 前3章完读率预期达标
□ 付费节点位置已确定（番茄第6章/起点第35章）
□ 至少1个钩子设计在每章结尾
□ 结局走向已确定（避免烂尾）
□ 格式安全规则已内置
```

### 3.4 成稿门禁检查项

```
□ 通过 writing-safety 全维度自检
□ 对话占比达标（番茄≥60%/起点≥50%）
□ 无Markdown表格/敏感符号
□ 每段≤3行，单句≤20-25字
□ 每章结尾有钩子
□ 战力无崩坏
□ 人设无OOC
□ 逻辑无漏洞
□ 伏笔有回收
□ 爽点有铺垫有反馈
```

### 3.5 异常处理机制

```
场景一【构思门禁未通过】
→ 停在第二步，不允许进入大纲阶段
→ 指出具体未通过项，给出修改建议
→ 等待用户确认后重新通过门禁

场景二【大纲门禁未通过】
→ 停在第三步，不允许进入写作阶段
→ 常见原因：节奏规划不符合平台算法要求
→ 使用 pacing + fanqie/qidian 专家重新调整

场景三【成稿门禁未通过】
→ 停在当前章节，不允许进入下一章
→ 使用 logic + writing-safety 定位问题
→ 修改后重新通过门禁再继续

场景四【中途更换题材/平台】
→ 回退至第二步，重新通过构思门禁
→ 角色设定和世界观需要相应调整
→ 不要试图"凑合用"原来的设定
```
