# 生成->评审->修正循环（REVISE-LOOP）

> **定位**：质量门禁的执行层。quality-gate 检测出问题后，由本 skill 决定如何修正、由谁修正、修正到什么程度。
> **触发**：expert-quality-gate Post-Write 验证未通过时自动触发。
> **理论基础**：Self-Refine（arXiv:2303.17651）——LLM通过迭代反馈+修正可提升约20%的任务表现。
> **联动**：quality-gate（检测）-> 本skill（调度修正）-> 对应expert（执行修正）-> quality-gate（复检）

---

## 一、修正循环流程

```
初稿生成
  |
  v
quality-gate 检测 -> 输出问题清单（按类型分类）
  |
  +-> 全部通过 -> 输出
  |
  +-> 存在问题 -> 进入修正循环
        |
        v
   Round 1: 自动修正（精确修复，<=3段）
   - 定位问题段落
   - 按类型分配修正expert
   - 仅替换问题段落
   - 重新 quality-gate
   - 通过 -> 输出
   - 未通过 -> Round 2
        |
        v
   Round 2: 深度修正（段落/场景重写）
   - 定位整个场景（>3段影响范围）
   - 调用expert重写整个场景
   - 重新 quality-gate + 剧情校验
   - 通过 -> 输出
   - 未通过 -> Round 3
        |
        v
   Round 3: 升级决策（人类介入）
   - 生成「问题诊断报告」
   - 标记问题章节
   - 输出给用户 + 2-3个建议方案
   - 等待用户决策
   - 不再自动修正
```

## 三、剧情推进校验（Plot-Pace-Checker）

> **核心问题**：用户只给大致剧情方向，AI 输出后节奏过快或完全偏移。
> **解决**：每章输出后，实时对照 PLOT-FRAMEWORK 检查推进速度。

### 3.1 五维校验体系

**维度一：情节推进速度**
- 本章是否完成了规划中分配的任务？
- 是否过早推进了后续章节的内容？
- 是否把3章的内容压缩到了1章？
- 判定标准：
  - 规划中本章是铺垫章但输出包含了爽点爆发 -> 过快
  - 规划中本章是日常章但输出推进了主线剧情 -> 偏移
  - 一章内完成了规划中2章以上的内容 -> 严重过快

**维度二：情感节奏**
- 角色关系变化是否自然？
- 是否跳过了情感过渡直接到结果？
- 一章内角色关系从陌生到亲密 -> 过快
- 检查点：对话亲密度、肢体接触级别、心理活动变化

**维度三：爽点密度**
- 规划中本章没有爽点但输出给了爽点 -> 过密
- 连续3章无任何爽点 -> 过稀
- 爽点类型是否多样化（打脸/升级/揭秘/团聚/反转）？
- 计算：本卷已用爽点数 vs 规划爽点数

**维度四：世界观揭示**
- 是否过早揭示了规划中后期才出现的设定？
- 信息密度是否过高（一章揭示过多新设定）？
- 示例：第一部只用3种噬种/3档饕餮/3级境界 -> 多了就是过载
- 检查点：新名词/新体系/新规则的出现频率

**维度五：伏笔处理**
- 是否过早回收了规划中后期的伏笔？
- 是否埋了新伏笔但没有记录到bookstatus？
- 伏笔密度是否合理（每3-5章一个新伏笔）？
- 检查点：悬念设置、线索铺垫、真相暗示

### 3.2 校验输出格式

```
剧情推进校验 ChXX
  推进速度: 正常/偏快/严重过快
  情节完成度: 本章完成了规划中[具体内容]
  偏移检测: [是否包含未规划的内容]
  情感节奏: 正常/突兀
  爽点密度: 正常/过密/过稀
  世界观: 正常/过早揭示/信息过载
  伏笔: 正常/过早回收/未记录新伏笔
  判定: 通过 / 需修正（具体问题）
```

### 3.3 节奏异常修正策略

**症状一：一章推进了2-3章的内容**
1. 拆分：将当前章节拆为2-3个独立章节
2. 补充：在被跳过的位置插入过渡章（日常/对话/心理）
3. 减速：将快速推进的内容改为铺垫+暗示，结果推后
4. 更新 PLOT-FRAMEWORK：调整后续章节规划

**症状二：情感跳跃（陌生->亲密太快）**
1. 插入过渡场景（尴尬/试探/距离感）
2. 将亲密场景改为暗示而非直述
3. 增加其他角色的旁观视角

**症状三：爽点过密（连续给爽）**
1. 将部分爽点改为铺垫而非爆发
2. 插入压力/困境章节
3. 调整爽点类型（从打脸改为揭秘/情感）

**症状四：世界观信息过载**
1. 将新设定分散到多章中渐进揭示
2. 用角色对话自然引入，而非旁白说明
3. 先展示现象，后解释原理

**症状五：伏笔过早回收**
1. 将回收改为暗示（读者感觉到但不确定）
2. 推迟到更合适的高潮位置
3. 增加误导信息，保持悬念

## 四、修正策略细则

### 4.1 Round 1: 自动修正（精确修复）
适用: 单点问题，影响范围 <= 3段
策略:
1. 定位问题段落（精确到段号）
2. 分析问题根因（模板/重复/逻辑/节奏）
3. 调用对应 expert 生成修正内容
4. 仅替换问题段落，不改动其余部分
5. 重新 quality-gate 验证
6. 通过 -> 输出; 未通过 -> Round 2

示例:
  问题: 第3段有模板残留（"就在这时，一股强大的力量..."）
  修正: 调用 expert-anti-ai-taste 重写第3段
  验证: quality-gate A类检测

### 4.2 Round 2: 深度修正（段落重写）
适用: Round 1 未通过，或问题影响 > 3段
策略:
1. 定位问题所在的整个场景/段落
2. 分析该场景在全章中的功能（推进/铺垫/高潮）
3. 保持功能不变，用不同手法重新实现
4. 调用 expert 重写整个场景
5. 重新 quality-gate + 剧情校验
6. 通过 -> 输出; 未通过 -> Round 3

示例:
  问题: 节奏过快，3章内容压缩在1章
  修正: 拆分为2章，补充过渡内容
  验证: quality-gate + plot-pace-checker

### 4.3 Round 3: 升级决策（人类介入）
适用: Round 2 仍无法通过
动作:
1. 输出当前内容（标注具体问题位置）
2. 输出「问题诊断报告」
3. 等待用户决策
4. 不再自动修正（避免无限循环消耗tokens）

诊断报告格式:
  [FAIL] ChXX 修正失败（Round 3）
  问题: [描述]
  已尝试:
    Round 1: [方案] -> 未通过（原因）
    Round 2: [方案] -> 未通过（原因）
  建议方案:
    A. [方案描述]
    B. [方案描述]
    C. 跳过本章，标记为待处理
  请选择->

## 六、防止无限循环

```
安全机制:
- 最多3轮自动修正
- 每轮修正后必须重新 quality-gate 验证
- 同一问题类型连续2轮未通过 -> 直接跳到 Round 3
- Round 3 不再自动修正，等用户决策
- 所有修正消耗的tokens计入会话预算
```
