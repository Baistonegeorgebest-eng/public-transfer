# 个性化写作风格学习专家（v1.0）

> **定位**：让 AI 从"模型默认味"进化成"用户自己的笔风"。
> **核心机制**：用户修改 → 提取差异 → 存入记忆 → 下次遵循 → 循环迭代
> **联动**：novel-expert-system（生成时读取 .user-style.md）、expert-writing-safety（风格不违反安全规范）

---

## 一、为什么需要这个

现状问题：所有 expert 生成的文风都是"模型默认"，每个用户用同一个系统写出一样的味道，用户不得不手动修改，但系统从不学习。

解决方案：.user-style.md = 用户的"风格指纹"
- 首次：通用风格生成，用户修改，提取差异
- 第二次：按用户风格生成，修改量下降
- 第N次：几乎不需要修改，AI已经"变成"用户了

---

## 二、.user-style.md 文件规范

### 2.1 存放位置

项目根目录/.user-style.md，与 .bookstatus.md / .footprint.md / ERRORS.md 同级。

### 2.2 文件格式

```markdown
# 【风格指纹】[项目名]
> 建立时间：YYYY-MM-DD
> 最后更新：YYYY-MM-DD
> 已学习章数：N章
> 平均修改率：N%（越低越好）

---

## 句式偏好

| 规则 | 说明 | 来源 | 置信度 |
|------|------|------|--------|
| 短句为主 | 平均句长≤20字，长句占比<20% | Ch1-5修改 | ⭐⭐⭐ |
| 对话不用"说道"标签 | 不加"他说道""她回应道" | Ch3批注 | ⭐⭐ |

## 段落偏好

| 规则 | 说明 | 来源 | 置信度 |
|------|------|------|--------|
| 段落≤5行 | 短段落 | Ch2-8统计 | ⭐⭐⭐ |
| 对话单独成段 | 每句对白独立段落 | Ch4批注 | ⭐⭐ |

## 描写偏好

| 规则 | 说明 | 来源 | 置信度 |
|------|------|------|--------|
| 心理描写少 | 用户大量删除心理独白 | Ch1-10删除统计 | ⭐⭐⭐ |
| 动作>心理>环境 | 描写优先级 | Ch5批注 | ⭐⭐ |

## 节奏偏好

| 规则 | 说明 | 来源 | 置信度 |
|------|------|------|--------|
| 对话占比≥40% | 对话驱动 | Ch1-10统计 | ⭐⭐ |
| 章末必须有钩子 | 不能平淡收尾 | Ch6批注 | ⭐⭐⭐ |

## 用词黑名单

```
不由得 / 眼神中闪过一丝 / 不禁 / 一种说不清的 / 心中暗想 / 嘴角微微上翘
（从用户反复删除的词汇中自动积累）
```

## 用词白名单

```
（用户特别喜欢的表达方式，从用户主动添加的内容中提取）
```

## 平台特定风格

| 平台 | 特殊要求 |
|------|---------|
| 番茄 | 前三句必须抓人，句式变化防AI检测 |
| 起点 | 本章说互动引导，信息密度高 |
```

### 2.3 置信度

- ⭐ 低：仅1-2次观察，可能是偶然
- ⭐⭐ 中：3-5次一致观察
- ⭐⭐⭐ 高：5次以上一致观察，或用户明确表达

## 三、学习机制

### 3.1 三种学习方式

**方式A：从用户修改中学习（被动）**
- 流程：生成 → 用户修改 → 对比差异 → 提取规则
- 频率：每章生成后

**方式B：从用户批注中学习（主动）**
- 流程：用户说"我不喜欢XX" / "以后不要用XX" / "我喜欢XX的写法"
- 频率：随时

**方式C：定期差异统计（批量）**
- 流程：每5章，统计用户修改的模式
- 频率：每5章

### 3.2 差异提取流程

```
Step 1：对比原文 vs 用户修改版
  → 找出被删除的/添加的/替换的内容

Step 2：分类差异
  → 句式差异（长句改短句 / 被动改主动）
  → 用词差异（删除特定词汇 / 替换为偏好词汇）
  → 描写差异（删除心理描写 / 增加动作细节）
  → 节奏差异（对话比例变化 / 段落长度变化）

Step 3：判断是否为稳定偏好
  → 仅1次 → 不记录
  → 2-3次 → 低置信度规则
  → 4次以上 → 高置信度规则

Step 4：写入 .user-style.md
```

### 3.3 学习示例

原文："他不由得皱起了眉头，眼神中闪过一丝复杂的情绪，心中暗想这件事不太对劲。"
修改："他皱眉。不对。"

提取规则：
1. 短句偏好（19字→6字，压缩70%）→ 置信度+1
2. 用词黑名单：不由得、眼神中闪过一丝、心中暗想 → 加入黑名单
3. 心理描写大幅压缩 → "心理描写少"置信度+1

## 四、与其他 Skills 的联动

### 4.1 生成前：注入风格约束

novel-expert-system 调用 expert 生成时：
1. 读取 .user-style.md
2. 将风格规则转化为 prompt 约束

示例注入：
```
【风格约束（来自 .user-style.md）】
- 短句为主（平均句长≤20字）
- 禁止使用：不由得、眼神中闪过一丝、心中暗想
- 对话占比≥40%，心理描写尽量精简
- 段落不超过5行
- 章末必须有钩子
```

### 4.2 生成后：对比差异学习

用户修改章节后：
1. 对比原文 vs 修改版
2. 提取差异规则
3. 更新 .user-style.md

### 4.3 与 quality-gate / footprint 的关系

- quality-gate 管"对不对"（硬性标准）— 优先级最高
- style-learner 管"像不像你"（个性化标准）— 不违反安全规范的前提下
- footprint 禁止列表 → 继承到 .user-style.md 用词黑名单
- style-learner 学习成果 → 通用条目反哺 footprint

## 五、启动与初始化

### 5.1 新项目

```
Step 1：检查参考项目 .user-style.md
  ├─ 存在 → 复制为初始版本，清零统计数据
  └─ 不存在 → 创建空白 .user-style.md

Step 2：告知用户
  "已创建 .user-style.md。随着你修改章节，系统会自动学习你的写作风格。"
```

### 5.2 从已有项目迁移

如果用户有已完成项目（如气功砍穿神魔301章）：
1. 对比原稿 vs 用户最终版
2. 批量提取风格规则
3. 生成 .user-style.md 初始版本
→ 新项目从第一天就按用户风格生成

## 六、修改率追踪

修改率 = 用户修改字符数 / 原文总字符数 × 100%

目标曲线：
- 第1章：40-60%（正常，系统不了解用户）
- 第5章：20-35%（系统开始学习）
- 第10章：10-20%（系统基本了解用户）
- 第20章+：5-15%（系统已接近用户风格）

在 .user-style.md 头部维护修改率趋势。

---

## 七、安全边界

1. 风格学习不能违反 expert-writing-safety 的安全规范
   → 用户偏好"血腥描写多" → 不学习（违反平台规则）
   → 用户偏好"短句" → 学习（安全偏好）

2. 风格学习不能违反 expert-footprint 的禁止列表
   → 用户偏好"月光/烛火开篇" → 不学习（属于机械错误模板）

3. 风格学习优先级低于质量门禁
   → quality-gate 不通过 → 必须修正，不管是否符合用户风格
   → 两者冲突时，quality-gate 获胜
