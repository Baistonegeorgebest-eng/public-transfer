# 项目间禁止列表继承机制（v2.3）

> 核心工作流见SKILL.md。

---

## 背景

每个项目在创作过程中都会积累禁止列表（🚫），这些经验教训对新项目同样有价值。但之前的机制是项目隔离的——新项目从零开始，重复犯老错误。

**实战教训**：气功砍穿神魔积累了12条禁止列表条目，但美食末世启动时完全从零摸索，浪费了大量试错时间。

## 全局基础禁止列表

```
🚫 全局基础禁止列表（v2.3，自动继承）

通用类：
1. 无情节绑定的"暮色降临"场景描写（A类/B类）
2. 无情节绑定的"夜色渐深"万能章节结尾（C类）
3. 无情节绑定的"烛火/壁炉/月光"室内描写（E类）
4. 五感清单式机械罗列（视觉→听觉→嗅觉→触觉逐项）（D类）
5. "他深吸一口气"作为章节开头的无功能填充
6. "一种说不清的情绪涌上心头"万能心理填充
7. "脚步轻移，身体微微侧转"万能动作填充
8. 连续3章使用相同类型的章节开头（如都是对话/都是场景）
9. 章节结尾总是同一类型（总是悬念/总是反转/总是感慨）
10. 角色出场总是先描写外貌再描写性格的模板化流程

batch类（有batch历史的项目额外继承）：
11. 任何非单章模式的批量生成操作
12. batch生成后不做语义级质检（F类）即放行
```

## 继承机制

```
新项目启动时：
① 自动加载全局基础禁止列表（本节上方）
② 如果有参考项目，额外加载参考项目的.footprint.md中的禁止列表
③ 合并去重后，写入新项目的.footprint.md

项目运行中：
④ 新发现的重复写法 → 添加到本项目.footprint.md
⑤ 如果条目具有通用性（不限于本项目）→ 同时追加到全局基础禁止列表

项目结束时：
⑥ 将本项目禁止列表中有通用价值的条目 → 追加到全局基础禁止列表
⑦ 在 novel-memory.md 中记录本次新增的通用禁止条目
```
