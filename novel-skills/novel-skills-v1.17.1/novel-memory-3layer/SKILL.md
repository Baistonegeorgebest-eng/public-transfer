# 长篇小说三层记忆管理体系

> 实测项目：气功砍穿神魔（300章·已验证ch1-20）
> 核心目标：写章节时只读必要信息，不加载全量原文，避免伏笔遗漏和剧情跑偏

---

## 三层架构

```
第一层：core-anchors.md（≤3000字，每次写作前必读）
  → 男主状态 / 力量体系 / 当前剧情 / 核心伏笔 / 角色状态 / 禁忌清单
  → 合并所有设定文件的精简版
  → 每卷结束时追加新内容，不删旧内容

第二层：mini-summary-chN-N.md（每10章≤1000字，按需检索）
  → 本阶段核心事件
  → 伏笔回收状态
  → 角色状态变化
  → 能量/战力状态变化
  → 下一阶段待处理伏笔
  → 每10章创建，写ch21前读ch11-20

第三层：原文归档（不投喂）
  → ch001.txt ~ ch300.txt
  → 存本地，模型不读取
  → 必要时人工查阅
```

---

## 写作流程

```
① 写chN前 → 读core-anchors.md（全局锚点）
② 写chN前 → 读mini-summary（当前10章区间事件/伏笔状态）
③ 写chN前 → 读ch{N-1}最后200字（接续感）
④ 写chN → 完整单章输出（不分段，2200-2800字）
⑤ 写完后 → 增量事实快照（见下方）
⑥ 写完后 → 更新core-anchors（如有重大剧情变化）
⑦ 每10章 → 创建/更新mini-summary
```

### ⑤ 增量事实快照（每章必做）

每章写完后，**立即**在当前 mini-summary 的"下一阶段待处理"中追加本章增量事实：

```markdown
- ⚡ ch{N}增量：
  · 确认事实：[本章确认的关键事件/设定]
  · 新设定：[本章引入的新概念，是否与core-anchors兼容]
  · 角色变化：[本章角色状态变化]
  · 伏笔：[本章埋入/回收的伏笔]
```

**为什么每章都做**：LCAS V3.1 验证——每轮对话后提取增量事实，作为下一轮逻辑基础，比等10章才更新mini-summary的遗忘率低得多。成本极低（几句话），收益明确（伏笔不遗漏、设定不跑偏）。

**与⑦的关系**：⑤是增量追加（几句话），⑦是结构化整理（≤1000字全文）。⑤保连续性，⑦保可读性。

## 与豆包建议的区别

| 豆包建议 | 本方案 |
|---------|--------|
| 拆段生成（1200字×2） | ❌ 不拆，完整单章输出 |
| "tokens降95%" | ✅ 实际节省：只读锚点+摘要，不读原文 |
| QMD语义检索 | ✅ 用memory_search或直接读文件 |
| 三层记忆架构 | ✅ 采纳并验证 |

**关键取舍**：采纳三层记忆架构，拒绝拆段生成。拆段破坏叙事节奏，而我们单章输出无中断问题。
