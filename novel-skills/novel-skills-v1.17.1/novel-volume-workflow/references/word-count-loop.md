## 十二、字数验证与自动扩写（v1.4新增）

> 解决子代理产出字数不足的问题。核心思路：prompt精确化（事前）+ 自动扩写循环（事后）。

### 12.1 两层控制

#### 第一层：Prompt精确化（事前预防）

每章prompt必须包含事件清单+字数锚点：

```
【PLOT-FRAMEWORK信息】
本章：ch73「标题」（目标2500字）
事件清单：
 ① 威尔登门 → 张力展开（600字）
 ② 威压叠加 → 感知描写（500字）
 ③ 试探交锋 → 对话+冲突（500字）
 ④ 收尾 → 内心独白（400字）
 ⑤ 尾声 → 能量/伏笔（500字）
字数底线：2000字（窄口径），低于此数自动扩写后再提交。
```

#### 第二层：自动扩写循环（事后验证）

```
产出字数 < 2000字 → 自动扩写
扩写清单（每次注入1-2项，按优先级轮转）：
 ① 增加感官细节（视觉/听觉/触觉）  ← expert-sensory-prose
 ② 增加内心独白
 ③ 增加环境/氛围描写
 ④ 增加过渡动作描写
 ⑤ 增加对话
 ⑥ 增加配角反应/群像描写
```

### 12.2 扩写循环执行流程

```
【第N章写完 → quality-gate验证 → 字数检查】

Step 1：统计字数
  → python3 -c "
    import sys
    text = open('chXX.txt').read()
    cn = sum(1 for c in text if '\u4e00' <= c <= '\u9fff')
    print(f'窄口径字数: {cn}')
  "
  → cn ≥ 2000 → 通过，进入Step 6
  → cn < 2000 → 进入Step 2

Step 2：计算差额，确定扩写轮次
  → 差额 ≤ 300字 → 1轮（注入1项扩写清单）
  → 差额 301-600字 → 2轮（每轮注入2项）
  → 差额 > 600字 → 3轮（每轮注入2项）

Step 3：选择扩写位置
  → 优先扩写最短的事件/场景
  → 次选：对话密集段可加反应描写
  → 避免：在结尾堆砌，破坏节奏

Step 4：执行扩写
  → 注入选定的扩写清单项
  → 子代理/agent重写指定段落
  → 不改动已通过质检的其他内容

Step 5：重新验证
  → 重新统计字数
  → 重新走 quality-gate 验证
  → cn ≥ 2000 → 通过，进入Step 6
  → 仍<2000且轮次未满 → 回到Step 3
  → 3轮后仍<1800字 → 标记⚠️「字数不足」提交人工处理

Step 6：更新 .bookstatus.md + .footprint.md
```

### 12.3 扩写参数（可按项目调整）

```
项目默认值（气功砍穿神魔）：
  目标字数：2000-3000字（窄口径）
  扩写下限：2000字
  人工终判线：1800字（3轮后仍不足）
  最大扩写轮次：3轮

特殊场景调整：
  高燃章节（⭐标记）：目标3000-4000，下限2500
  日常过渡章：目标2000-2500，下限1800
  伏笔铺垫章：目标2000-2500，下限1800
  番茄短故事：目标1500-2000，下限1200
```

### 12.4 与强制调用链的集成

```
Phase 3 逐章执行（更新后）：
  正文创作
    ↓
  expert-writing-safety 合规检查
    ↓
  expert-quality-gate Post-Write验证
    ↓
  [新增] 字数验证 → <2000字 → 扩写循环（最多3轮）
    ↓  (通过)
  expert-footprint 防重复扫描
    ↓
  expert-revise-loop 剧情推进校验
    ↓
  ...后续步骤不变
```

### 12.5 扩写质量要求

扩写不是灌水，每次扩写必须满足：
- ✅ 新增内容与当前场景上下文一致
- ✅ 新增内容推进剧情或深化角色（不能只是形容词堆砌）
- ✅ 扩写后重新通过 quality-gate 全量检查
- ❌ 禁止：用AI模板句填充字数
- ❌ 禁止：在已有描写后重复换说法
- ❌ 禁止：添加与本章无关的"回忆杀"凑字数
