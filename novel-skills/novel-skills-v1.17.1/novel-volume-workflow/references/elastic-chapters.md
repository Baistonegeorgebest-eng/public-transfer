## 十三、小说弹性章节机制（v1.3新增）

> 对接 novel-expert-system 附录「弹性章节范围原则」。每卷50~85章弹性，基于质检和剧情需要自动判定是否扩充。

### 13.1 弹性范围

```
基础范围：50~85章/卷（每章窄口径2000-3000字）
最低标准：50章（不可低于，否则节奏不够）
弹性上限：85章（超过说明该拆为两卷）
特殊平台：番茄短故事30~50章/卷

字数锚定：章数弹性不影响字数目标
  50章 × 2500字 = 12.5万字（基础）
  85章 × 2500字 = 21.25万字（弹性上限）
```

### 13.2 触发扩充的条件（质检驱动）

在逐章执行过程中，以下条件触发弹性扩充评估：

| # | 触发条件 | 扩充类型 | 典型场景 |
|---|---------|---------|---------|
| E1 | 感情线发展太快 | +2~5章感情过渡 | 角色关系从陌生到亲密缺少铺垫 |
| E2 | 支线未展开 | +3~5章支线 | NPC背景/副线剧情需要展开 |
| E3 | NPC钩子需要加深 | +1~3章NPC篇 | 重要NPC死亡冲击不够/角色弧光未完成 |
| E4 | 打Boss太简单 | +2~4章升级冲突 | 战斗过程一笔带过，缺少波折和反转 |
| E5 | 爽点铺垫不足 | +1~3章铺垫 | 读者感受不到爽点的"爽"因为缺少对比 |
| E6 | 世界观展示不足 | +2~3章日常/探索 | 读者对世界规则理解不够 |
| E7 | 伏笔回收需要空间 | +1~2章过渡 | 多条伏笔需要同时回收但空间不够 |
| E8 | 追读率下滑诊断 | +2~4章节奏调整 | reader-tracker检测到数据异常 |
| E9 | 擦边/亲密场景需要 | +1~2章情感升温 | 剧情需要但不能突兀跳过 |
| E10 | 卷末高潮不够震撼 | +2~3章终极铺垫 | 最终决战缺少层层递进的紧张感 |

### 13.3 扩充评估流程

```
当质检或剧情推进校验触发扩充条件时：

Step 1：确认触发条件
  -> 是哪个条件（E1-E10）？
  -> 需要增加多少章（参考范围）？

Step 2：确定插入位置
  -> 在哪两章之间插入？
  -> 插入的章节在PLOT-FRAMEWORK中的位置

Step 3：设计新增章节
  -> 每章的主Expert + 协同Expert
  -> 字数目标
  -> 关键内容
  -> 与前后章节的衔接

Step 4：更新框架
  -> PLOT-FRAMEWORK新增行（后续编号+1）
  -> .bookstatus.md 章节索引更新
  -> 执行索引一致性检查（§2.2）

Step 5：输出评估报告
  -> 为什么扩充
  -> 扩充了几章
  -> 插入位置
  -> 对总章节数的影响
```

### 13.4 扩充评估报告格式

```
弹性扩充评估
  项目：[书名]
  卷次：第X卷
  触发条件：[E1-E10] + 具体描述
  当前进度：已完成ChXX，规划至ChYY
  建议扩充：+N章（ChXX.5 ~ ChXX.N）
  插入位置：ChXX 与 ChXX+1 之间
  扩充理由：[详细说明]
  新增章节规划：
    ChXX.5：[标题] | 主Expert: xxx | 字数: 2500 | [内容概要]
    ChXX.6：[标题] | 主Expert: xxx | 字数: 2500 | [内容概要]
  总章节数变化：XX章 -> XX+N章
  是否超出弹性上限：是/否（上限85章）
  请确认→
```

### 13.5 与质检链的集成

```
Phase 3 逐章执行中：
  每章写完 -> 走8步质检链
  质检通过 -> 剧情推进校验（Plot-Pace-Checker）
  校验发现需要扩充 -> 触发§13.3评估流程
  用户确认 -> 插入弹性章节 -> 继续推进
  用户拒绝 -> 标记警告但继续按原计划推进

自动触发 vs 人工确认：
  E1/E2/E3/E5/E6/E9 -> 建议扩充，等用户确认
  E4/E8 -> 强烈建议扩充（影响质量）
  E7/E10 -> 直接扩充（伏笔回收和卷末高潮是硬需求）
```

### 13.6 结束条件（满足任一即结束本卷）

```
① 主线爽点已完成（例：斩杀Boss/打败强敌）
② 已达章节上限（85章）
③ 追读率出现明显下滑趋势（需调整节奏开新卷）
④ 角色弧光完成（主角本卷成长目标达成）
⑤ 伏笔已回收（本卷伏笔全部处理完毕）
⑥ 平台首秀期结束（番茄21天/起点PK通过）
```
