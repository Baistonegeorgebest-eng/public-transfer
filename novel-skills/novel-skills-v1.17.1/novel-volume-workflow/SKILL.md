# 卷级创作全流程（VOLUME-WORKFLOW）

> **定位**：解决"必须手动调用每个 skill"的核心痛点。用户说一句话，agent 自动走完全链路。
> **触发关键词**：写第X卷、推进XX、开始新卷、继续写、接着写、开卷、卷级规划
> **联动**：novel-expert-system（路由入口）→ 本workflow（编排中心）→ 各expert按链调用

---

## 〇、核心原则

用户说"推进第X卷" ≠ 帮我写一章
用户说"推进第X卷" = 走完整个卷级工作流

工作流 = 规划（一次）→ 执行（多章）→ 验证（每章）→ 更新（每章）

用户不应该需要：
  - 手动说"调用expert-memory回顾伏笔"
  - 手动说"调用expert-plot-shuangdian设计爽点"
  - 手动说"调用expert-footprint检查重复"
  - 手动说"更新BOOK-STATUS"
  - 手动说"检查章节编号一致性"

这些全部自动执行。用户只需要：
  + "推进第二卷" → 走完全链路
  + "继续写" → 从上次停下的地方继续
  + "第45章重写" → 单章修复流程

## 一、全链路流程

### Phase 0：项目状态恢复（每次启动必做）
1. 检查 .bookstatus.md 是否存在
2. 不存在 → 扫描目录，自动创建
3. 存在 → 读取，加载项目上下文
4. 验证索引一致性（文件数 vs 记录数）
5. 输出：当前状态摘要

### Phase 1：卷级规划（新卷启动时执行）
1. expert-memory：加载前情/伏笔/人物状态
2. expert-worldbuilding：确认世界观一致性
3. expert-plot-shuangdian：设计本卷爽点链
4. expert-pacing：规划节奏曲线+章节数
5. expert-character：角色弧光规划
6. expert-emotion：情感线推进节点
7. expert-hook：标记关键钩子章节
8. expert-footprint：扫描历史防重复基线
9. expert-serialization-ops：平台节奏适配
10. expert-platform-metrics：数据标准确认
输出：PLOT-FRAMEWORK.md（全卷规划表）

### Phase 2：章节预标注
对规划表中每一章，预标注：
- 主调用 expert（1个）
- 协同 expert（2-3个）
- 字数目标（窄口径2000-3000）
- 弹性标记（可扩展/不可删）

### Phase 3：逐章执行（循环）
1. 读取本章规划+预标注skills
2. expert-memory：本章伏笔/前情检查
3. expert-footprint：防重复扫描
4. **人味扰动注入**（见下方§3b）→ 为本章随机选择2-3条扰动规则
5. 正文创作（调用预标注的主+协同expert，叠加负向约束+过程模拟+节奏模板）
6. expert-quality-gate：Post-Write验证
6b. 若字数<2000字（窄口径）→ 扩写循环（最多3轮，见§十二）
7. expert-writing-safety：合规检查
8. expert-anti-ai-taste：人味过程审计（替代旧的事后去AI味检查）
9. 更新 .bookstatus.md
10. 更新 .footprint.md
11. 弹性评估：是否需要插入额外章节？

#### §3b 人味扰动注入（强制·每章执行）

> 目的：引入随机性，模拟人类写作的不确定性。每次从以下7条中随机选2-3条执行，不要每次都选同样的。

```
【扰动规则·概率触发】

30%概率：本章有一段对话被环境打断（有人进来/有噪音/被叫走）
30%概率：本章有一个角色说了句跟当前话题无关的话
20%概率：本章有一个段落只有1句话（极端节奏变化）
20%概率：本章有一个角色说话被打断，且没有继续说完
15%概率：本章有一个细节读者看不懂为什么要写（比如谁在剥指甲）
15%概率：本章有一句话明显比其他句子写得粗糙（像赶工）
10%概率：本章结尾没有任何收束感，就是事情停在那儿了

执行记录：
  - 在质检报告中记录本章使用了哪几条扰动
  - 避免连续3章使用完全相同的扰动组合
  - 记录到 .footprint.md 防重复
```

**扰动效果对比：**

无扰动版：
> 会议室里坐满了人。林无味把经历说了一遍。老赵打破了沉默。陈晓站在门口反驳。长老做出裁决。

有扰动版：
> 会议室里坐满了人。角落有个哥们儿在抠鞋底的泥，抠了半天没抠下来。
> 林无味把经历说了一遍——蓄水池、影噬群、炎噬、巢穴。说到肉质地表的时候他停了一下，不知道该怎么描述那种手感。
> "死了十二个人。"老赵说。说完咳了两声。感冒了好像。
> ……
> 会开到一半有人推门进来问晚饭吃什么。被长老瞪了一眼，缩回去了。

### Phase 4：卷级终审
1. expert-quality-gate：全卷质检
2. expert-memory：伏笔回收完整性检查
3. expert-pacing：全卷节奏终审
4. expert-logic：逻辑一致性终审
5. 更新 .bookstatus.md 卷状态为完成
6. 打包输出

## 二、Phase 0：项目状态恢复（强制执行）

### 操作步骤

Step 1：定位项目目录
- 扫描 workspace 中的项目目录
- 如果只有一个项目，直接加载
- 如果多个项目，列出让用户选择

Step 2：检查 .bookstatus.md
- 存在：读取全部内容，加载到上下文
- 不存在：进入自动创建流程

Step 3：自动创建 bookstatus（如不存在）
- 扫描目录中的 .txt/.md 章节文件
- 按文件名数字排序
- 统计每章字数
- 推断标题（从文件内容首行读取）
- 生成 .bookstatus.md
- 扫描关联文件（设定/伏笔/footprint）
- 填写文件关联节

Step 4：索引一致性验证（关键！）
- 对比：目录中章节文件数 vs bookstatus 记录数
- 对比：后续卷的起始编号 vs 本卷终章编号
- 对比：文件名中的章节编号 vs 文件内标题编号
- 不一致 → 自动修复或报告

### 索引一致性检查规则（血泪教训）

这是「美食末世」项目30→49章扩写后反复出错的核心教训。

必须检查的项目：
1. 目录中 .txt 文件数量 = bookstatus 章节索引行数
2. 文件名编号连续无断号（ch01, ch02, ... ch49）
3. 文件内标题编号与文件名一致
4. 后续卷的起始章节 = 本卷末章 + 1
5. PLOT-FRAMEWORK 中的章节编号与实际一致
6. 压缩包中的文件引用已更新
7. 全局搜索旧编号关键词（如"30章""Ch31"）无残留

修复规则：
- 文件名不连续：重命名为连续编号
- bookstatus 缺条目：从文件内容补全
- 后续卷编号错位：批量修正 + 全局搜索确认
- 旧编号残留：逐个修正

## 三、Phase 1：卷级规划（详细步骤）

### 3.1 前情加载（expert-memory）
1. 读取前卷的 BOOK-STATUS.md 章节索引
2. 读取伏笔追踪表，列出已回收/未回收/新埋伏笔
3. 读取人物关系表，确认当前状态
4. 读取时间线，确认故事当前时间点
5. 输出摘要：前情 → 本卷起点 → 关键待处理项

### 3.2 世界观校验（expert-worldbuilding）
1. 读取世界观设定文件
2. 确认本卷新出现的设定是否与已有设定矛盾
3. 确认战力体系/境界等级是否在当前可展示范围内
4. 标注「本卷新揭示」vs「已有设定引用」

### 3.3 爽点链设计（expert-plot-shuangdian）
1. 根据前情和世界观，设计本卷的爽点节奏：
   - 小爽点：每3-5章一个
   - 中爽点：每10-15章一个
   - 大爽点：卷末高潮
2. 每个爽点标注：章节位置、爽点类型、前置铺垫章节、后续反馈章节

### 3.4 节奏规划（expert-pacing）
1. 确定本卷总章节数（含弹性区间）
2. 划分幕结构（3-4幕）
3. 每幕标注：章节范围、核心主题、节奏类型、字数区间
4. 标注弹性节点（可扩展位置/不可压缩位置）

### 3.5 角色弧光（expert-character）
1. 确认本卷涉及的主要角色
2. 每个角色标注：进入状态、目标状态、转变章节、OOC风险点

### 3.6 情感线（expert-emotion）
1. 确认本卷情感线走向
2. 标注情感节点章节
3. 标注需要 expert-emotion-death 的章节（如有）

### 3.7 钩子预标记（expert-hook）
1. 在每幕开头/结尾/卷末预标记钩子
2. 钩子类型选择：悬念型/反转型/情感型/揭秘型

### 3.8 防重复基线（expert-footprint）
1. 读取 .footprint.md
2. 标注已有的高频模式/禁止列表
3. 为本卷新增内容设定 freshness 基线

### 3.9 平台适配（expert-serialization-ops + expert-platform-metrics）
1. 确认目标平台的当前算法指标
2. 确认更新节奏要求和字数标准
3. 标注需要数据监控的节点

### 3.10 输出：PLOT-FRAMEWORK.md
综合以上所有分析，生成完整的卷级规划文件。位置：[项目目录]/第X卷/PLOT-FRAMEWORK.md

## 四、Phase 2：章节预标注

PLOT-FRAMEWORK 中每章的预标注格式：

| 章节 | 标题(暂定) | 主Expert | 协同Expert | 字数目标 | 关键内容 | 弹性 | 状态 |
|------|-----------|----------|-----------|---------|---------|------|------|
| Ch50 | [标题] | expert-fanqie-novel | hook+pacing+memory | 2500字 | [一句话] | 固定 | 待写 |

标注规则：
- 主Expert：本章最核心的1个 expert
- 协同Expert：2-3个辅助 expert，用+连接
- 字数目标：窄口径 2000-3000字
- 弹性标记：固定=不可删 / 可扩展=可插入额外章 / 可压缩=可合并
- 状态：待写→写作中→草稿→完成

## 五、Phase 3：逐章执行（自动化）

### 每章工作流（自动触发，不需要用户手动调用）

准备写第N章时，agent 自动执行：
1. 读取 PLOT-FRAMEWORK 中第N章的规划 → 获取主Expert、协同Expert、字数目标
2. expert-memory 检查 → 回顾前一章结尾 + 确认伏笔 + 人物状态
3. expert-footprint 扫描 → 对照禁止列表 + freshness评级
4. 正文创作 → 按预标注的主Expert + 协同Expert调用
5. expert-quality-gate Post-Write 验证 → 模板/字数/连续性/节奏/J类重复
6. expert-writing-safety 合规检查
7. 通过 → 更新 .bookstatus.md + .footprint.md + PLOT-FRAMEWORK
8. 未通过 → 修复后重新验证，不输出未通过的内容
9. 弹性评估 → 检查进度vs节奏，决定是否插入额外章节

### 弹性增加章节的评估标准

触发条件（满足任一即评估）：
- 角色关系需要更多铺垫
- 爽点前置铺垫不足
- 日常/生活描写太少
- 情感线跳跃太快
- 支线需要展开

评估流程：
1. 确定插入位置
2. 确定类型和内容
3. 确定对后续编号的影响
4. 更新 PLOT-FRAMEWORK + bookstatus
5. 执行索引一致性检查
6. 输出变更说明

## 六、Phase 4：卷级终审

全卷完成后执行：
1. expert-quality-gate 全卷质检

3. expert-pacing 节奏终审
4. expert-logic 逻辑终审

## 七、与 novel-expert-system 的集成

### 路由规则
当用户输入包含以下关键词时，路由到本 workflow：
- "写第X卷" / "推进第X卷" / "继续写" / "接着写"
- "开始新卷" / "开卷" / "卷级规划" / "规划第X卷"
- "推进XX"（XX为书名或卷名）

路由优先级：高于单个 expert（卷级任务需要编排多个 expert）

### 与现有路由的区分
单章任务 → 走单expert路由（如"帮我写一段战斗"→expert-combat）
卷级任务 → 走本workflow（如"推进第二卷"→novel-volume-workflow）
