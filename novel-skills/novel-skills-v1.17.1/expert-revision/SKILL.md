## 第一章 改稿的本质认知

### 1.1 初稿 vs 二稿 vs 终稿的本质区别

**初稿是"给自己的"** — 核心任务：把故事从脑子里搬到纸上。不需要完美，需要的是完成。

初稿的特点：
- 逻辑跳跃正常（写的时候脑子里有完整画面）
- 对白啰嗦正常（还不知道哪句话是关键）
- 节奏不均匀正常（在探索故事走向）

**二稿是"给故事的"** — 核心任务：让故事本身变得完整、自洽、有力。

二稿关注点：因果链完整？伏笔回收？人物弧线？高潮位置？

**终稿是"给读者的"** — 核心任务：让读者获得最好的阅读体验。

终稿关注点：每句话通顺？用词精准？开头抓人？结尾有余韵？

### 1.2 为什么改稿必须"由大到小"

**铁律：永远从最大的问题开始改，最后改最小的问题。**

原因：如果你先改字词，再发现整个场景需要删掉，之前所有修改都白费。

类比装修：拆墙（结构）→ 水电（情节）→ 墙面（场景）→ 家具（句子）→ 装饰（字词）。

### 1.3 改稿心态：从"作者"切换为"读者"

**切换技巧：**
1. **冷却法** — 至少放24小时，最好3天以上
2. **换个环境** — 打印出来看或用手机看
3. **读出声** — 声音会暴露默读时自动脑补掉的问题
4. **假装是别人的作品** — 想象这是你在网上随便找到的小说

## 第二章 五层改稿递进法

### 2.1 结构层修改（第一遍）

结构问题解决了，很多下层问题会自动消失。

**（1）章节合并/拆分/重排**
- 每章3000-5000字，至少一个转折或高潮点
- 一章什么都没发生 → 合并或重写
- 信息量爆炸 → 拆成两章，在关键位置断章

**（2）删除支线**
- 每条支线必须回答："对主线有什么影响？"
- 没有直接影响 → 90%应该删掉
- 删掉的内容存到素材库

**（3）调整节奏曲线**
- 张弛有度：紧张→放松→紧张→高峰→回落
- 连续三章同一节奏 = 读者疲劳或弃书
- 网文建议：每10-15章小高潮，30-50章大高潮

### 2.2 情节层修改（第二遍）

**（1）因果链检查**
- 逐场景检查因果关系：A导致B，B导致C
- 允许巧合出现在"麻烦"上，不允许出现在"解决方案"上

**（2）伏笔回收验证**
- 列出所有伏笔清单：第几章埋的、预计第几章收、实际收了没有
- 检查"幽灵伏笔"（看起来像伏笔但忘了处理）
- 检查"硬收伏笔"（强行解释前文无关描写）

**（3）高潮位置优化**
- 高潮前要有足够铺垫（情绪蓄力）
- 最大高潮出现在全书70%-80%
- 结尾高潮后留出"收尾空间"

### 2.3 场景层修改（第三遍）

**场景功能明确化：每个场景必须完成一个任务。**

任务类型：① 推进情节 ② 揭示信息 ③ 发展人物 ④ 建立关系 ⑤ 营造氛围

**无效场景判断：**
- 能否一句话概括？不能 = 无效
- 删掉后后面能无缝衔接？能 = 无效
- 和上个场景相比有新信息？没有 = 冗余

### 2.4 句子层修改（第四遍）

**（1）句式多样化** — 连续5句以上相同结构必须改
**（2）节奏感调整** — 紧张用短句，抒情用长句
**（3）冗余删除** — "开始"类废话、重复说明、无意义过渡句

### 2.5 字词层修改（第五遍）

**（1）和谐词检查** — 提交前检查是否触发审核
**（2）用词精准度** — 一个精准动词胜过三个形容词
**（3）方言/口语统一** — 角色语言风格前后一致

## 第三章 初稿病诊断与治疗

### 3.1 八大初稿病速查

| 排序 | 病症 | 核心药方 | 修改层次 |
|------|------|---------|---------|
| ① | 节奏拖沓 | 砍掉每章开头过渡段，直接从事件切入 | 结构层 |
| ② | 对话无信息 | 每句对白至少完成一个功能 | 场景层 |
| ③ | 场景冗余 | 合并功能重叠场景，删除不明确的 | 场景层 |
| ④ | 逻辑跳跃 | 补充铺垫，增加动机说明 | 情节层 |
| ⑤ | 情感突兀 | 增加情绪渐变描写 | 情节层 |
| ⑥ | 人物脸谱化 | 每个角色一个独特说话方式/矛盾面 | 场景层 |
| ⑦ | 开头无力 | 直接从事件切入，背景后补 | 结构层 |
| ⑧ | 结尾仓促 | 增加"回落期"1-2个场景 | 结构层 |

### 3.2 逐章打分诊断法

每章5维度打分（1-5分）：

| 分数 | 节奏 | 信息 | 情感 | 对白 | 逻辑 |
|------|------|------|------|------|------|
| 1 | 完全拖沓 | 零信息 | 无感 | 全废话 | 不通 |
| 3 | 合格 | 有信息 | 有感觉 | 有功能 | 通顺 |
| 5 | 大师级 | 密度极高 | 泪目 | 经典 | 完美 |

**诊断规则：**
- 单章任一维度≤2分 → 该章必须修改
- 连续3章同一维度≤3分 → 系统性问题，需结构层面审视
- 全书平均分≤3分 → 建议大改

## 第四章 改稿工具与流程

### 4.1 冷却法

```
最短：24小时（日更连载）
推荐：3-7天（中短篇）
理想：2-4周（长篇大改/出版级）

冷却期间：不读刚写完的东西，去读同类型优秀作品
```

### 4.2 自读法（朗读全文）

朗读迫使大脑按线性速度处理，暴露默读时跳过的问题。

**标记：** 所有拗口的/想跳过的/觉得"好长"的地方

**工具推荐：** TTS听一遍 / 手机录音回放

### 4.3 反向大纲法

```
1. 不看原大纲，从成品中提取每个场景一句话摘要
2. 将提取摘要和原大纲对比
3. 找差异：原大纲有但成品没有的？成品有但原大纲没有的？顺序不同？
```

### 4.4 他人反馈的处理

**核心原则：永远关注读者对问题的描述，而不是他们给的解决方案**

**三人原则：** 一个人说 = 个人偏好；三个人说同一个问题 = 大概率真有问题

**处理流程：** 收集→分类→找共性→对照改稿计划→决定采纳与否

## 第五章 改稿优先级矩阵

### 5.1 三级优先级

**P0级（不改不能发布）：** 逻辑硬伤、伏笔断线、重大情节漏洞、视角/时间线混乱

**P1级（发布前尽量改完）：** 节奏不均、对白质量差、场景冗余、人物弧线不完整

**P2级（改了更好）：** 字词不精准、句式单一、细节不足、个人风格偏好

### 5.2 优先级排序公式

```
优先级 = 严重程度 × 影响范围 ÷ 修改成本

示例：
  逻辑硬伤：5×3÷2=7.5 → 必须改
  节奏拖沓：4×5÷3=6.7 → 优先改
  字词微调：2×1÷1=2.0 → 最后改
```

### 5.3 实操建议

```
第一遍：只改P0级问题
第二遍：改P1级问题
第三遍：挑选性地改P2级问题
最后：通读检查
```

## 自检清单

### 五层自检
- [ ] 结构层：章节划分合理，无注水章节，节奏张弛有度
- [ ] 情节层：因果链完整，伏笔全回收，高潮位置合理
- [ ] 场景层：每个场景有功能，无冗余，开头直接切入
- [ ] 句子层：句式多样，无冗余废话，朗读无拗口
- [ ] 字词层：无和谐词，动词精准，角色语言一致

### 综合自检
- [ ] 冷却24小时后重新通读
- [ ] 至少朗读一遍全文
- [ ] 反向大纲与原大纲对比无重大偏差
- [ ] 收集至少3人反馈并处理共性问题
- [ ] P0级问题全部解决
