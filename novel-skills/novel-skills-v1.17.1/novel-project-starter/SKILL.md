# 小说项目一键启动器（v1.0）

> **核心理念**：用户不需要学任何东西。说人话就行，系统自己搞定。
> **触发条件**：任何表达"想写/要写/开一本小说"意图的自然语言。
> **联动**：novel-expert-system（专家调度）、expert-bookstatus（状态文件）、expert-footprint（防重复）、expert-style-learner（风格学习）

---

## 一、触发识别

### 1.1 自然语言触发（无需记忆关键词）

用户说以下任意表达时，自动触发本 skill：

```
明确意图：
  "我要写一本小说" / "我想写个新书" / "开一本新书" / "开坑"
  "帮我写个穿越文" / "想写个末世题材的" / "新项目"
  "开始写鬼灭同人" / "写一本番茄上的都市爽文"

模糊意图（也触发，但需确认）：
  "我有个想法，穿越+系统流" / "最近想搞个新东西"
  "帮我规划一下新书" / "你觉得重生文怎么写"

不触发：
  "继续写" / "推进" / "下一章" / "接着写" → 这是继续已有项目，走 novel-expert-system
```

### 1.2 信息自动提取

从用户的一句话中，尽可能推断以下信息：

| 信息 | 提取方式 | 示例 |
|------|---------|------|
| **题材** | 关键词匹配 | "穿越"→穿越、"末世"→末世、"都市"→都市、"同人"→ACG同人 |
| **平台** | 关键词匹配 | "番茄"→番茄、"起点"→起点、"晋江"→晋江 |
| **核心卖点** | 语义理解 | "重生打脸"→重生+打脸、"系统流升级"→系统流+升级 |
| **参考作品** | 提取书名/作品名 | "类似诡秘之主的"→参考：诡秘之主 |
| **目标读者** | 推断 | 番茄→男频，晋江→女频，未提→待确认 |
| **项目名** | 从描述中提取或用户指定 | "穿越异界之神王投影"→项目名 |

### 1.3 信息缺失处理

```
如果能推断 ≥ 3项关键信息（题材+平台+核心卖点）→ 直接创建，不问
如果缺失 1-2项 → 只问缺失的那几项，最多2个问题
如果信息太少 → 问3个核心问题（见下一节）
```

## 二、启动对话模板

### 情况A：信息充足（直接创建）

用户："我要写一本番茄上的末世美食流爽文"

系统直接执行，不问问题：
```
好的，末世+美食+番茄+爽文，开搞。

📋 已创建项目「末世美食」
├── 项目目录：~/workspace/末世美食/
├── .bookstatus.md（时间线+角色状态+伏笔追踪已启用）
├── .footprint.md（全局12条禁止列表已继承）
├── .user-style.md（风格学习已启用）
├── ERRORS.md（失败记录已启用）
├── .learnings/（跨章节记忆已启用）
│   ├── CHARACTERS.md
│   ├── LOCATIONS.md
│   ├── PLOT_POINTS.md
│   └── STORY_BIBLE.md
└── 已加载专家：
    ├── 题材：expert-fanqie-novel（番茄男频）
    ├── 技法：expert-emotion + expert-dialogue + expert-combat
    ├── 质量：expert-quality-gate + expert-writing-safety
    └── 辅助：expert-footprint + expert-style-learner

🎯 接下来你想怎么走？
A. 直接出大纲（我给方向，系统出6卷大纲）
B. 先聊设定（世界观/力量体系/主角人设）
C. 给我一个爆款开篇（直接写第1章）
```

### 情况B：信息不足（只问必要的）

用户："我想写个小说"

系统：
```
三个问题，30秒搞定：

1. 什么题材？（穿越/都市/末世/修仙/同人/其他？）
2. 发哪个平台？（番茄/起点/晋江/其他？）
3. 一句话说说核心卖点？（比如"重生打脸"、"系统流升级"、"恋爱甜宠"）
```

用户回答后 → 执行情况A的流程。

### 情况C：有参考作品

用户："我想写个类似诡秘之主的，但放在番茄上，偏爽一点"

系统：
```
收到：参考《诡秘之主》的克苏鲁+序列体系，番茄化（爽文化），保留悬疑核心。

📋 已创建项目「（待命名）」
加载了：expert-suspense（悬疑）+ expert-fanqie-novel（番茄男频）+ expert-worldbuilding（世界观）
参考作品：诡秘之主 → 已记录，生成时会参考其世界观结构和节奏模式

项目名叫什么？（或者我帮你起一个？）
```

## 三、自动创建的文件清单

每个新项目启动时，自动创建以下文件（用户不需要手动创建任何东西）：

```
项目目录/
├── .bookstatus.md          ← 项目状态（含时间线+角色状态+伏笔追踪）
├── .footprint.md           ← 防重复（继承全局12条禁止列表）
├── .user-style.md          ← 风格学习（空白，随写作积累）
├── ERRORS.md               ← 失败记录（空白，质检失败时自动写入）
├── .learnings/             ← 跨章节记忆
│   ├── CHARACTERS.md       ← 角色档案
│   ├── LOCATIONS.md        ← 地点信息
│   ├── PLOT_POINTS.md      ← 情节转折
│   └── STORY_BIBLE.md      ← 世界观设定
├── PLOT-FRAMEWORK.md       ← 卷级框架大纲（待填充）
└── memory/novel-projects/
    └── [项目名].md         ← 项目子记忆
```

（空，创作过程中自动积累）

## 五、后续引导

项目创建完成后，给用户三个明确的下一步选项：

```
🎯 接下来你想怎么走？

A. 📝 直接出大纲
   → 系统根据你的一句话方向，生成6卷大纲 + 爽点矩阵
   → 你审核修改，系统学习你的偏好

B. 💬 先聊设定
   → 世界观 / 力量体系 / 主角人设 / 反派动机
   → 聊完后系统生成设定总表 → STORY_BIBLE.md

C. ✍️ 直接开写
   → 跳过大纲，从第1章开始
   → 系统按单章模式生成，附带质检报告
   → 你修改，系统学习你的风格

D. 🎲 给我个惊喜
   → 系统根据题材+平台，自动出一个完整的开篇方案
   → 包括：书名+简介+前3章大纲+核心卖点分析
```

## 六、与现有 Skills 的联动

```
用户说"我想写XXX"
  → novel-project-starter（本skill）：创建项目结构 + 加载专家
    → expert-bookstatus：创建 .bookstatus.md
    → expert-footprint：继承禁止列表 → 创建 .footprint.md
    → expert-style-learner：创建 .user-style.md
    → expert-memory：创建 .learnings/ + 项目子记忆
    → novel-expert-system：进入六步体系
      → 用户选择A → 第一步（世界观构建）
      → 用户选择B → 第一步（世界观构建·对话模式）
      → 用户选择C → 第三步（正文创作）
      → 用户选择D → 全流程自动
```

---

## 七、注意事项

1. **不要问太多问题**——能推断的就推断，最多问2-3个
2. **不要解释 skill 的存在**——用户不需要知道底层调了什么
3. **创建后给明确的下一步**——不要让用户在一堆文件面前发呆
4. **第一次交互就建立风格基线**——.user-style.md 从第1章开始学习
5. **允许用户随时修改**——推断错了没关系，用户说"不对，是起点不是番茄"就改
