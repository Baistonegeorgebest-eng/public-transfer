# 项目状态文件专家（BOOKSTATUS）

> **定位**：统一管理每个小说项目的元信息、章节索引、进度状态、文件关联。
> **v2.0增强**：时间线/角色状态/伏笔追踪从"文件关联引用"升级为**内嵌强制模块**，每章必须同步更新。
> **触发条件**：新建创作项目时（强制创建）；每写完一章时（强制更新全部7个步骤）；切换项目时（状态检查）。
> **联动**：被 novel-expert-system 初始化流程调用，被 expert-memory / expert-footprint / expert-quality-gate 引用。

---

## 一、为什么需要 BOOKSTATUS

```
当前问题：
  1. 多项目并行时不知道每个项目"写到哪了"
  2. 重启会话后丢失进度上下文
  3. 章节索引散落在各处，没有统一入口
  4. 伏笔表、设定表、footprint 文件位置没有记录
  5. 平台数据（书名ID、签约状态、数据指标）无处存放
  6. agent 不知道项目是否存在，每次都要扫描目录
  7. 时间线/角色状态/伏笔追踪散落在不同文件，更新容易遗漏 ← v2.0新增问题

BOOKSTATUS 解决：
  → 一个文件 = 项目全部状态
  → agent 开机读这个文件就知道该干什么
  → 章节索引自动维护，不再手动
  → 文件关联一目了然
  → 时间线/角色状态/伏笔追踪内嵌文件，拒绝更新遗漏 ← v2.0核心升级
```

## 📅 时间线（内嵌·每章强制更新）

> **必须内嵌在 .bookstatus.md 中**，不另开文件。格式：| 绝对天数 | 章节 | 故事时间 | 关键事件 | 影响范围 |
> 每章写完后立即追加一行。不允许跳过。

| 绝对天数 | 章节 | 故事时间 | 关键事件 | 影响范围 |
|---------|------|---------|---------|---------|
| 第1天 | Ch1 | 春·清晨 | 主角穿越 | 全书起点 |
| 第3天 | Ch3 | 春·黄昏 | 进入宗门 | 宗门线开启 |
| 第15天 | Ch8 | 夏·正午 | 第一次宗门大比 | 势力关系变化 |

**更新规则**：
- 每章写完后，如果本章推进了故事时间，追加一行
- "绝对天数"从故事起点开始累计，不依赖具体日期
- 同一天内多章只记录关键事件变化，不重复日期行
- 时间线必须连续，不允许跳跃（需补充中间节点则注明"时间流逝"）

---

## 🎭 角色状态（内嵌·每章强制更新）

> **必须内嵌在 .bookstatus.md 中**，不另开文件。格式：| 角色 | 位置 | 情绪 | 物品/装备 | 身体/特殊状态 | 最后出场 |
> 每章写完后立即更新对应角色的状态行。新角色出现时追加一行。死亡角色标记为 ~~删除线~~ 但保留记录。

| 角色 | 位置 | 情绪 | 物品/装备 | 身体/特殊状态 | 最后出场 |
|------|------|------|-----------|--------------|---------|
| [主角] | [当前位置] | [当前情绪] | [持有物品] | [健康/受伤] | Ch[N] |
| [配角A] | [位置] | [情绪] | [物品] | [状态] | Ch[N] |
| ~~[死亡角色]~~ | — | — | — | 已死亡 | Ch[N] |

**更新规则**：
- 关键事件（战斗/离队/立场变化/获得重要物品）后立即更新
- 无重大变化时每5章刷新一次
- 物品获得/失去 → 更新"物品/装备"列
- "最后出场"字段必须与章节索引一致

---

## 🔮 伏笔追踪（内嵌·每章强制更新）

> **必须内嵌在 .bookstatus.md 中**，不另开文件。格式：| ID | 埋入章 | 伏笔内容 | 类型 | 预期回收章 | 实际回收章 | 状态 |
> 每章写完后检查：如有新伏笔→追加行；如有伏笔回收→更新状态。Never leave a foreshadowing in "active" without review.

| ID | 埋入章 | 伏笔内容 | 类型 | 预期回收章 | 实际回收章 | 状态 |
|----|-------|---------|------|-----------|-----------|------|
| F01 | Ch3 | [伏笔描述] | 道具 | Ch27 | Ch27 | ✅已回收 |
| F02 | Ch5 | [伏笔描述] | 剧情 | Ch45 | — | 🔄进行中 |
| F03 | Ch8 | [伏笔描述] | 角色 | Ch36 | — | ⏳待回收 |

**伏笔类型**：剧情 / 道具 / 身份 / 角色 / 战力 / 情感

**状态标记**：
- ⏳待回收：已埋入，未到预期章节
- 🔄进行中：正在铺垫，即将回收
- ✅已回收：已完成回收
- ❌已过期：预期章节已过，未回收 → 需立即处理
- 🗑️已放弃：经评估无回收价值，已合理消除悬念

**更新规则**：
- 埋入伏笔时立即登记（不要相信"我能记住"）
- 回收伏笔时标记 ✅ + 实际回收章节
- 伏笔状态为"待回收"超过10章 → 标记 ⚠️预警
- 每章结束后必须检查一次，不允许"没检查"就跳过

## 三、创建流程（强制执行）

当 agent 开始一个新项目（或首次加载已有项目）时：

```
Step 1：检查 .bookstatus.md 是否存在
  ├─ 存在 → 读取，获取当前状态
  └─ 不存在 → 进入 Step 2

Step 2：创建 .bookstatus.md
  ├─ 扫描项目目录，收集已有文件
  ├─ 填写项目元信息（从用户对话中提取）
  ├─ 初始化进度概览（从已有章节文件计算）
  ├─ 建立章节索引（从已有 .txt 文件推断）
  ├─ 初始化📅时间线（扫描已有章节，提取关键事件→逐章填入）
  ├─ 初始化🎭角色状态（扫描已有章节，提取出场角色→逐个填入）
  ├─ 初始化🔮伏笔追踪（扫描已有章节，识别伏笔→逐条登记）
  ├─ 关联已发现的文件路径
  └─ 写入 .bookstatus.md

Step 3：验证
  ├─ 文件路径是否正确指向已存在的文件
  ├─ 章节数量与目录中 .txt 文件数量是否匹配
  ├─ 字数统计是否合理
  └─ 三大内嵌模块（时间线/角色/伏笔）是否有初始数据
```

## 四、更新流程（每章完成后强制执行）

每写完一章时，agent 必须按顺序执行以下全部步骤（不允许跳过任何一步）：

```
Step 1：更新章节索引
 ├─ 追加新行：| N | [标题] | [字数] | [关键事件] | 📝草稿 |
 └─ 若本章为已发布状态 → 将📝草稿改为✅已发布

Step 2：更新📅时间线（强制）
 ├─ 推算"绝对时间"：根据章节节奏判断（如：战斗篇3天/日常篇1周）
 ├─ 追加一行：| [绝对天数] | ChN | [故事时间] | [本章核心事件] | [对后续影响] |
 └─ 时间线必须连续，不允许跳跃（需补充中间节点则注明"时间流逝"）

Step 3：更新🎭角色状态（强制）
 ├─ 扫描本章涉及的所有角色
 ├─ 更新其位置/情绪/物品/身体状态
 ├─ 新角色出现 → 追加新行
 ├─ 角色死亡 → 保留行但加删除线
 └─ 物品获得/失去 → 更新"物品/装备"列

Step 4：更新🔮伏笔追踪（强制）
 ├─ 本章是否出现新伏笔？→ 追加新行（状态:active）
 ├─ 本章是否回收了旧伏笔？→ 更新对应行（状态:已回收）
 ├─ 伏笔状态是否为"待回收"超过10章？→ 标记⚠️预警
 └─ 每章结束后必须检查一次，不允许"没检查"就跳过

Step 5：更新进度概览
 ├─ 总章节数 +1
 ├─ 总字数 +本章字数
 ├─ 最后更新章节 → 本章
 ├─ 最后更新时间 → 当前时间

Step 6：质检结果写入（重要）
 ├─ 本章质检通过 → 无需操作
 ├─ 本章质检失败 → 自动写入 .learnings/ERRORS.md
 │ 追加格式：[YYYY-MM-DD ChN] [严重程度] [问题类型] - [描述]
 └─ 失败次数≥3次的章节 → 标记🔴阻断，暂停推进

Step 7：写入变更日志
 └─ 追加一行：| YYYY-MM-DD | 新增第N章 | [章节名] |
```

> **强制检查**：如果 agent 因任何原因跳过了 Step 2/3/4，必须在下一个可用时机补全，禁止"时间线以后再说"。

## 五、与其他 Skills 的联动规则

### 5.1 novel-expert-system（初始化）

```
启动创作项目时：
  1. 调用 expert-bookstatus 检查 .bookstatus.md
  2. 不存在则创建
  3. 存在则读取并告知用户当前状态
```

### 5.2 expert-memory（设定/伏笔）

```
创建文件关联时：
  → .bookstatus.md 的「文件关联」节记录设定总表路径
  → .bookstatus.md 的「文件关联」节记录伏笔追踪路径
  → 每次伏笔调整后，检查 bookstatus 中路径是否仍然有效
```

### 5.3 expert-footprint（防重复）

```
创建文件关联时：
  → .bookstatus.md 的「文件关联」节记录 .footprint.md 路径
  → 每次 footprint 更新后，同步更新 bookstatus 的最后更新时间
```

### 5.4 expert-serialization-ops（运营数据）

```
数据监控时：
  → 读取 .bookstatus.md 的「平台数据」节获取基线
  → 数据变化时回写更新
  → 断更天数从 bookstatus 的最后更新时间计算
```

### 5.5 expert-quality-gate（质量门禁）

```
Post-Write 验证时：
  → 确认 .bookstatus.md 已同步更新（7步全部完成）
  → 检查新章节的字数与 bookstatus 记录是否一致
  → 质检失败时写入 .learnings/ERRORS.md（Step 6）
```

## 六、BOOKSTATUS 自动发现机制

当 agent 进入「长篇小说及规划」目录时，应：

```
1. 扫描所有子目录中的 .bookstatus.md
2. 列出所有项目及其状态
3. 根据「当前状态」排序：连载中 > 存稿中 > 草稿期 > 已断更 > 已完结
4. 提示用户选择要操作的项目
```

## 七、故障处理

### 7.1 BOOKSTATUS 丢失

```
症状：项目目录存在但 .bookstatus.md 缺失
处理：
  1. 扫描目录中的 .txt 文件（章节）
  2. 扫描设定/伏笔/footprint 文件
  3. 重新创建 .bookstatus.md（含三大内嵌模块初始化）
  4. 章节索引从文件名推断（按数字排序）
  5. 标记为「重建」状态
```

### 7.2 章节索引不同步

```
症状：目录中 .txt 文件数量 ≠ bookstatus 记录章节数
处理：
  1. diff 对比差异
  2. 对缺失条目：从文件内容提取标题和字数，补入索引
  3. 对多余条目：删除（可能是临时文件）
  4. 同步更新三大内嵌模块
```

### 7.3 文件路径失效

```
症状：bookstatus 中记录的路径指向不存在的文件
处理：
  1. 尝试在项目目录内搜索同名文件
  2. 找到则更新路径
  3. 找不到则标记为 ⚠️丢失
```
