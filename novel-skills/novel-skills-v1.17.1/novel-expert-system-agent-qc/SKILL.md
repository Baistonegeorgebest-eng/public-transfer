# 多Agent质控体系

> **触发条件**：涉及批量写作质检、评审打分、润色优化时激活。
> **加载来源**：novel-expert-system 子模块。

## 第六步：多Agent质控体系（2026新增·实测验证版）

> 来源：worker 产出参差不齐问题根因分析 + 四层质量控制方案
> 适用场景：批量章节 worker 协作时保证输出质量稳定

### 6.1 问题根因

| 问题 | 原因 |
|------|------|
| 产出忽好忽坏 | worker 每次都是全新 session，无质量参照物 |
| 字数不稳定 | 未明确字数下限 |
| 格式不一致 | 未规定结构规范 |
| 方向偏离 | 缺少前章锚点作为衔接约束 |

### 6.2 四层质量控制体系

#### 第一层：注入前——指令即质量标准

精简指令包必须包含"自检清单"，worker 输出前必须逐项核对。

**精简指令包标准结构**：

```
## 任务
[具体写作任务描述]

## 前章结尾锚点（必须衔接）
「[上一章结尾的2-3句话原文]」
→ 本章开头必须接着写：[衔接方向指引]

## 合格标准（输出前自检）
- [ ] 字数 ≥ XXX字
- [ ] 每段 ≤ 3行
- [ ] 对话占比 ≥ 60%
- [ ] 开篇XXX字内有冲突
- [ ] 结尾有钩子（下一章悬念）
- [ ] 禁用心理描写（禁止"他想""她觉得"）
- [ ] 衔接前章（禁止与前章矛盾）

## 输出
- 正文写入：[文件路径]
- 自检通过后才算完成
```

#### 第二层：注入中——前章锚点锁定方向

前章结尾原文直接注入，作为不可违背的衔接约束。

```
## 前章结尾锚点（必须衔接，禁止矛盾）
「林远没有停步。身后传来苏母的声音：'林远！你别给脸不要脸！'」
→ 本章开头必须接着写：林远有没有回头？他上车后做了什么？
→ 禁止：让林远当场和苏母对峙（已走）
→ 禁止：让苏母突然变慈祥（情感逻辑断裂）
```

锚点越具体，偏方向几率越低。

#### 第三层：输出后——Reviewer Agent 评分验收

worker 写完后，过 Reviewer Agent 评分。

**Reviewer 精简评审指令包**：

```
## 评审任务
读取：/tmp/orch-test-v2/ch2-agent/outbox/chapter2.txt

## 评分标准（1-5分）
① 字数达标（≥1000字）：达标5分 / 800-999字3分 / <800字0分
② 开篇冲突（300字内出冲突）：达标5分 / 有冲突但位置偏3分 / 无冲突0分
③ 格式正确（每段≤3行，对话≥60%）：完全达标5分 / 基本达标3分 / 不达标0分
④ 衔接前章（无矛盾）：衔接良好5分 / 有小断层3分 / 矛盾0分
⑤ 结尾钩子（强钩子拉追读）：强5分 / 弱3分 / 无0分
⑥ 禁用心理描写：完全符合5分 / 有1-2处3分 / 多处0分

## 评审输出格式
总分：X/30
①：X分  ②：X分  ③：X分  ④：X分  ⑤：X分  ⑥：X分
问题：[列出具体问题，最多3条]
结论：接受 / 打回重写

## 决策规则
- 总分≥24分（80%）：接受，合并到正文
- 总分18-23分：打回重写，指明具体问题
- 总分<18分：主agent亲自重写，不用该worker结果
```

**Reviewer token 消耗**：约 3k tokens（很少，但能拦截大部分不合格输出）

#### 第四层：合并后——主Agent统一润色

所有章节通过 Reviewer 后，主 agent 统一润色。

```
## 润色任务
合并以下章节文件，输出统一润色版本：
- /workspace/项目/outbox/ch01.txt
- /workspace/项目/outbox/ch02.txt
- [其他章节...]

## 润色要求
- 保持各章节风格基本一致
- 消除重复使用的相同表达
- 优化章节间的过渡句
- 总字数误差控制在±5%以内
- 润色消耗 token 很少（各章节已达标，只需微调）
```

### 6.3 完整工作流（全流程图）

```
主Agent（协调者）
│
├── Step 1：读取skill，生成精简指令包（含锚点+自检清单）
│
├── Step 2：spawn Worker-A（第1-3章）、Worker-B（第4-6章）、Worker-C（第7-10章）
│   └── 各worker独立执行，互不干扰，并行运行
│
├── Step 3：各worker输出后，spawn Reviewer Agent（评审各章节）
│   └── 评分不达标 → 打回对应worker重写（最多重写1次）
│
├── Step 4：全部通过Reviewer后，主agent统一润色合并
│
└── Step 5：输出最终全文
```

### 6.4 实战参数（更新值）

| 参数 | 推荐值 | 说明 |
|------|-------|------|
| 每worker章数 | 2-3章 | 避免超时 |
| 精简指令字数 | ≤200字 | 含锚点+清单 |
| spawn超时 | 300秒 | 5分钟/2-3章 |
| Reviewer重写上限 | 1次 | 超限主agent接手 |
| 验收总分 | ≥24分接受 | 满分30分 |
| 润色时机 | 全部通过后 | 一次性统一润色 |

### 6.5 token 消耗估算（10章长篇）

| 阶段 | 单次消耗 | 次数 | 合计 |
|------|---------|------|------|
| 主agent读skill生成指令 | 37k | 1次 | 37k |
| 各worker执行（3组×5k） | 5k | 3次 | 15k |
| Reviewer评审（3组×3k） | 3k | 3次 | 9k |
| 重写（最坏情况3组×5k） | 5k | 3次 | 15k |
| 统一润色合并 | 8k | 1次 | 8k |
| **合计** | | | **~84k tokens** |

对比单agent全流程（37k×10章=370k）：**节省约77% tokens，同时质量更稳定**。
